# Movie Mood — Research

## Project Overview
Movie Mood is a small, cinematic movie-discovery React/TypeScript/Vite site hosted on GitHub Pages: https://soph1azhao.github.io/movie-mood/

Question it answers: What should I watch tonight? Pick a feeling → get three curated films with practical details, human discovery preferences, "not tonight" boundaries, related-film exploration, a save-for-later list, and a lightweight decision flow.

## Features
- Six mood-first entry points: funny, exciting, thought-provoking, relaxing, emotional, suspenseful
- Optional viewing situations: quiet solo, date night, friends, family movie night, easy-watch
- V3 discovery controls: attention demand, comfort-zone distance, strict "Not tonight" dealbreakers
- Practical filters: genre, runtime, language, pace, emotional weight
- Three focused recommendations at a time, "Another three" cycling
- V4 Decision Mode: three-film comparison, two-finalist duel, coin-flip gut check, Tonight's Pick ticket
- Shareable V4 decision URLs that restore context
- "More like this" mode (up to 3 related films)
- Expandable movie details
- Browser-local favorites in localStorage + My List view
- 34 curated films, TypeScript-typed, with committed TMDB factual snapshot
- Responsive, keyboard-friendly single-page interface
- Real TMDB poster images where available, CSS-generated Movie Mood title posters as fallback

Note: Normal app usage, tests, builds, and GitHub Pages deployment do NOT require a TMDB token. Poster images load from TMDB's image CDN when available.

## V5 Product Goal
Connect the completed Movie Mood experience to real movie data by enriching every existing curated movie with verified factual metadata and real poster imagery from TMDB.

Defining principle: Movie Mood owns meaning. TMDB owns facts.

Movie Mood continues to decide: why a movie fits a mood, how demanding it feels, emotional weight, familiarity/adventure, situations, discovery relations, what distinctions matter tonight.

TMDB supplies factual info. TMDB must NOT become the recommendation engine.

## Hard Architecture Constraints (V5)
Must remain: static, backend-free, database-free, account-free, GitHub Pages deployable, deterministic during normal use, understandable by one developer, inexpensive/free to operate, usable without runtime TMDB API access.

Do NOT add:
- backend services, serverless functions, databases, authentication, TMDB user auth, cloud persistence
- runtime TMDB data API calls from browser, browser-exposed TMDB API credentials
- automatic scheduled metadata refresh, GitHub Actions metadata sync
- TMDB search in product UI, universal movie catalogue browsing
- popularity-based ranking, vote/rating-based recommendation logic, AI-generated editorial annotations, ML
- React Router, Redux, Zustand, another state-management framework, TV support, streaming-provider availability
- broad redesign of V1–V4 interaction flows

Normal usage must remain a static client application.

## V5 Data Ownership Model (3 layers)

### 6.1 Movie Mood Identity
Every curated movie retains: id: string, tmdbId: number. ID remains authoritative inside Movie Mood. TMDB ID identifies the corresponding TMDB movie. TMDB ID must never replace Movie Mood ID in favorites, My List, URLs, recommendation state, decision state, similarity seed state.

### 6.2 Movie Mood Editorial Data
Movie Mood continues to own and manually curate: moods, situations, filterLanguages, pace, emotionalWeight, attentionDemand, discoveryStyle, description, whyWatch, curiosityHook, vibeSummary, palette. Description remains Movie Mood editorial copy (NOT TMDB overview). Palette remains for visual fallback when real poster unavailable.

### 6.3 TMDB Factual Data
TMDB supplies: title, year, director, countries, spokenLanguages, genres, runtimeMinutes, posterPath. Do NOT import: popularity, voteAverage, voteCount, trending rank, TMDB recommendations, TMDB overview, cast lists, backdrops, keywords, reviews, watch providers (unless explicitly required by future spec).

  countries: string[]
  spokenLanguages: string[]
  genres: string[]

### curatedMovies.ts
Hand-authored Movie Mood meaning layer. Contains: local ID, TMDB ID, Movie Mood editorial metadata.

### generated/tmdbMovies.json
Generated factual TMDB snapshot. Committed to Git. Never manually edited except when repairing corrupted repository state.

### movies.ts
Resolves: curated Movie Mood data + generated TMDB facts = Movie[]. Keep as normal application import where practical so V1–V4 components don't need unnecessary import churn.

## Generated Snapshot Schema
Uses Movie Mood local ID as top-level key:
{
  "movie-mood-stable-id": {
    "tmdbId": 123456,
    "title": "Example Movie",
    "year": 2024,
    "director": "Example Director",
    "countries": ["Example Country"],
    "spokenLanguages": ["Example Language"],
    "genres": ["Drama"],
    "runtimeMinutes": 108,
    "posterPath": "/example.jpg"
  }
}
Snapshot includes tmdbId so one-to-one correspondence can be validated. Do NOT key application by TMDB ID.

## Snapshot Determinism
Must be deterministic. No volatile fields: fetchedAt, updatedAt, popularity, voteAverage, voteCount, request timestamp, trending position. Normalize string arrays (genres, spokenLanguages, countries) by removing duplicates and producing stable ordering. Serialize local movie entries in stable curated dataset order or another explicitly deterministic order. Repeated sync against unchanged TMDB responses must produce no Git diff.

## TMDB Mapping Rules
Every V4 curated movie must receive exactly one manually verified tmdbId. Do NOT add/remove movies merely because V5 introduces TMDB. Requirements:
- every curated movie has one positive integer tmdbId
- every tmdbId maps to exactly one Movie Mood movie
- duplicate tmdbId values are invalid
- duplicate local IDs remain invalid
- existing Movie Mood local IDs must not change

A one-time TMDB search may be used by a maintainer to locate candidate IDs. BUT: The production synchronization command must never search by title or automatically choose a movie. Synchronization must fetch only the exact committed tmdbId. Candidate mapping should be reviewed using title, release year, director. Do NOT silently choose first search result.

## Maintainer-Time Synchronization
Add: pnpm sync:tmdb. Explicit maintainer operation.

Flow:
curatedMovies
      ↓
exact tmdbId values
      ↓
TMDB API
      ↓
validate all responses
      ↓
normalize all facts
      ↓
compare with existing snapshot
      ↓
write complete new snapshot

Synchronization is NOT part of: pnpm dev, pnpm test, pnpm build, GitHub Pages deployment. Normal application build must work without any TMDB credential.

## Authentication and Secret Handling
Use TMDB API Read Access Token through TMDB_READ_ACCESS_TOKEN environment variable. Token must be read from maintainer process environment.

Do NOT: commit a token, hard-code a token, serialize token into generated data, expose through import.meta.env, include in frontend code, place into built JavaScript bundle, print in logs, include in errors, place in normal GitHub Pages deployment config. If local env file used, must already be ignored or added safely to .gitignore. Prefer environment-based auth over command-line arguments containing the token.

## TMDB Request Scope
Use TMDB movie-details endpoint for each exact mapped movie ID. Single explicit localization: language=en-US. Use append_to_response for credits if needed so director info can be obtained without unnecessary request proliferation. Keep simple: sequential requests or very low concurrency, native platform HTTP/fetch. Do NOT add a TMDB SDK. Small dev-only script-running dependency acceptable only if genuinely needed. Do NOT add runtime application dependency merely for synchronization.

## TMDB Fact Normalization

### Title
Use localized TMDB movie title returned for configured language. Must be non-empty string.

### Year
Derive from TMDB release date. Missing or invalid release year is a synchronization failure.

### Runtime
Must be positive integer number of minutes. Missing, zero, negative, non-numeric, or otherwise invalid runtime is a synchronization failure. Behaviorally important because Movie Mood uses runtime for filters, dealbreakers, and decision contrasts.

### Genres
Use TMDB movie genre names. Must produce valid non-empty string array for current curated catalogue. Normalize deterministically.

### Spoken Languages
Use stable human-readable language names from TMDB's spoken-language data. Prefer English display names where available. TMDB spoken languages are factual display metadata. Must NOT replace Movie Mood's curated behavioral language filter values in Phase 1, because TMDB can include minor/incidental spoken languages that would alter existing filtering semantics. Normalize deterministically.

### Countries
Use TMDB production-country names. Normalize deterministically.

### Director
Derive from appended credits by crew entries identified as directors. If multiple directors exist, preserve all identified directors in one stable display string. Missing usable director for existing curated feature film is a synchronization failure.

### Poster
Store only: posterPath: string | null. Missing poster is allowed. Do NOT treat posterPath === null as synchronization failure.

## Explicit Synchronization Failure Policy
Synchronization is atomic: Either every curated movie produces one valid factual snapshot entry, or the existing generated snapshot remains unchanged. Never leave partially updated snapshot.

### Hard Data/Configuration Failures (fail immediately or fail sync)
TMDB_READ_ACCESS_TOKEN missing → Fail immediately. Do not modify snapshot.
Invalid/missing local movie ID → Fail.
Missing/invalid tmdbId → Fail.
Duplicate local ID → Fail.
Duplicate tmdbId → Fail.
TMDB 401 → Fail immediately. Do not retry as transient.
TMDB 403 → Fail immediately. Do not retry as transient.
TMDB 404 for committed tmdbId → Fail. Never search automatically for replacement.
Response movie ID differs from requested ID → Fail.
Invalid response structure → Fail.
Missing/invalid title → Fail.
Missing/invalid year → Fail.
Missing/invalid runtime → Fail.
Malformed required genre data → Fail.
Malformed required language data → Fail.
Missing usable director → Fail.
Snapshot count differs from curated movie count → Fail.
Snapshot cannot resolve one-to-one with curated data → Fail.

### Transient Failures (may be retried)
HTTP 429, HTTP 5xx, temporary network failures. Retry behavior must be bounded. Small fixed maximum number of attempts. Simple exponential/backoff. When Retry-After provided for rate limiting, respect where practical. If bounded retries exhausted: fail entire synchronization, preserve previous snapshot. Do NOT retry indefinitely.

### Allowed Graceful Degradation
posterPath === null is NOT a synchronization failure. At browser runtime, poster CDN image load failure must degrade gracefully to existing Movie Mood poster treatment. Movie recommendation functionality must remain usable without poster delivery.

## Atomic Write Requirement
Do NOT overwrite generated snapshot movie-by-movie. Synchronization must:
1. load and validate curated mapping
2. fetch all required TMDB records
3. validate every response
4. construct complete candidate snapshot
5. validate one-to-one correspondence
6. serialize complete deterministic candidate
7. only then replace existing generated snapshot

Safe implementation may write temporary file beside final snapshot and rename/promote only after complete validation. If any failure occurs before final promotion: existing snapshot remains untouched. Clean up temporary artifacts when practical.

## Behavior-Impact Classification
Not every factual TMDB change has same product impact. Sync report must distinguish:

### Behavior-impacting fields
runtimeMinutes, genres, filterLanguages — currently participate in filtering, dealbreakers, similarity, or other V1–V4 behavior. Changes must be prominently reported.

### Primarily display-oriented fields
title, year, director, countries, spokenLanguages, posterPath — should still appear in generated Git diff but do not currently define same filtering/similarity semantics.

## Initial V5 Behavior Review Gate (Phase 1)
Phase 1 is migration from existing hand-entered facts to first TMDB factual snapshot. Agent must compare first TMDB snapshot against existing V4 factual values before committing phase. If any behavior-impacting field differs (runtimeMinutes, genres, filterLanguages), agent must stop before commit and report concise review table containing: Movie Mood ID, movie title, field, old V4 value, new TMDB value. This is a deliberate human review gate and counts as valid reason to stop before commit under AGENTS.md. Do NOT change filtering/similarity algorithms merely to compensate for factual differences. After user approves factual changes, continue phase normally. Display-only differences do not require special stop unless they reveal likely incorrect TMDB mapping.

## V4 Architecture Notes
- src/App.tsx owns active DecisionState and resets it whenever upstream mood, situation, filter, discovery preference, view, or slate offset changes.
- src/components/DecisionMode.tsx renders three-slate comparison, duel, coin gut check, Tonight's Pick ticket.

- src/utils/urlCodec.ts serializes V4 decision URLs and validates decoded mood, situation, filters, discovery preferences, movie IDs against local dataset.
- While Decision Mode active, App keeps browser URL synchronized with current decision state. Valid V4 URLs restore preference context and decision phase on load; malformed or stale URLs fall back to normal start state.

## V5 Architecture Notes
- src/data/curatedMovies.ts owns Movie Mood meaning: local IDs, moods, situations, viewing/filter languages, experience fields, editorial copy, fallback poster palettes.
- src/data/generated/tmdbMovies.json is committed TMDB factual snapshot: title, year, director, countries, spoken languages, genres, runtime, poster path.

- src/components/MoviePoster.tsx centralizes TMDB poster URL usage and falls back to CSS title poster when posterPath missing or image fails to load.

## V5.1 Architecture Notes
- scripts/curateCore.mjs holds pure, testable Curation Assistant logic: local-ID suggestion, duplicate detection, candidate normalization, scaffold generation, orchestration with injected side effects.
- scripts/curateAdd.mjs is pnpm curate:add CLI wrapper. Performs network search and interactive selection, then writes curation draft to docs/curation-drafts/.
- Curation assistant does not decide Movie Mood editorial meaning. All taste, mood, editorial fields are TODO placeholders for maintainer to fill in.
- Curation assistant never writes to src/data/generated/tmdbMovies.json. pnpm sync:tmdb remains only normal producer of TMDB factual snapshot.
- src/utils/watchLinks.ts centralizes all external "Find where to watch" lookup URLs (general web search, TMDB web page, Letterboxd, JustWatch).
- src/components/WatchAction.tsx renders Tonight's Action links. Appears on Tonight's Pick ticket and Movie Details.
- Poster loading now reserves 2/3 aspect ratio before images load (layout stability), fades images in on load, keeps CSS title-poster fallback consistent on error.

## V5.1 — Adding Movies Safely (Curation Assistant)
pnpm curate:add "<movie title>" helps maintainer add new curated movie by reducing manual TMDB lookup and schema-copying work. Searches TMDB for given title, shows candidate matches in terminal, requires explicit maintainer selection — never auto-selects first result.

After candidate selected, assistant writes scaffold draft to docs/curation-drafts/<movie-id>.md with all CuratedMovie fields included as TODO placeholders. Maintainer then fills in Movie Mood meaning, adds entry to src/data/curatedMovies.ts, adds mapping to src/data/tmdbMovieMappings.json, runs pnpm sync:tmdb with TMDB_READ_ACCESS_TOKEN available to refresh generated facts.

pnpm curate:add "Perfect Blue"

Command requires TMDB_READ_ACCESS_TOKEN only for search step. Fails clearly and safely without modifying any project files if token missing, query empty, no candidates found, or selection cancelled.

Movie Mood meaning remains human-authored. Assistant does not guess moods, situations, pace, emotional weight, attention demand, discovery style, whyWatch, curiosityHook, vibeSummary, or filterLanguages.

## V5.1 — Tonight's Action
After Tonight's Pick, Movie Mood offers "Find where to watch" action with deterministic outbound links. These are external lookups, not verified streaming availability — app does not claim regional availability, provider logos, or real-time status.

## TMDB Snapshot Maintenance
pnpm sync:tmdb is maintainer-only command that refreshes committed TMDB snapshot from exact mapped TMDB IDs.

TMDB_READ_ACCESS_TOKEN=... pnpm sync:tmdb

Token read only from process environment. Must not be committed, exposed through import.meta.env, or added to GitHub Pages deployment.

Sync command validates complete snapshot before replacing it. Missing tokens, hard API/data failures, exhausted transient retries, duplicate mappings, one-to-one merge failures stop command without partially updating snapshot. Behavior-impacting runtime and genre changes are reported for review.

## Adding Movies and Filters
To add movie, update src/data/curatedMovies.ts with Movie Mood-owned fields including id, tmdbId, filterLanguages, situations, pace, emotionalWeight, attentionDemand, discoveryStyle, curiosityHook, vibeSummary, palette. Then add exact TMDB mapping and run pnpm sync:tmdb with TMDB_READ_ACCESS_TOKEN available so generated factual data refreshed. Keep IDs stable because favorites stored by ID.

Situation tags curated manually. Use family conservatively for broad family movie-night picks, do not treat as official age rating.

Future filters should be added first to shared types, then to pure filtering utility, and only after that to UI. Keep practical filters strict unless V2 spec explicitly changes fallback rule.

V3 experience labels are editorial categories, not scores. Keep attentionDemand and discoveryStyle categorical and avoid adding numerical recommendation percentages or hidden taste-profile data.

movies.ts (resolution layer):
import { curatedMovies } from './curatedMovies.js'
import tmdbMovies from './generated/tmdbMovies.json' with { type: 'json' }
import type { Movie, MovieFacts } from '../types/movie'

const factsByMovieId: Record<string, MovieFacts> = tmdbMovies

function resolveMovies(): Movie[] {
  const seenMovieIds = new Set<string>()
  const seenTmdbIds = new Set<number>()

  return curatedMovies.map((curatedMovie) => {
    if (seenMovieIds.has(curatedMovie.id)) {
      throw new Error(`Duplicate curated movie ID: ${curatedMovie.id}`)
    }
    if (seenTmdbIds.has(curatedMovie.tmdbId)) {
      throw new Error(`Duplicate curated TMDB ID: ${curatedMovie.tmdbId}`)
    }
    seenMovieIds.add(curatedMovie.id)
    seenTmdbIds.add(curatedMovie.tmdbId)
    const facts = factsByMovieId[curatedMovie.id]
    if (!facts) {
      throw new Error(`Missing TMDB facts for ${curatedMovie.id}`)
    }
    if (facts.tmdbId !== curatedMovie.tmdbId) {
      throw new Error(`TMDB ID mismatch for ${curatedMovie.id}`)
    }
    return {
      ...curatedMovie,
      ...facts,
      languages: curatedMovie.filterLanguages,
    }
  })
}

export const movies: Movie[] = resolveMovies()
